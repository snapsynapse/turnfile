# Contributing

Thank you for your interest in the Consensus Collaboration Protocol.

## How this project works

This protocol was developed through real multi-agent collaboration sessions and continues to evolve through practice. Contributions that come from real-world usage carry the most weight.

## Ways to contribute

### Use it and report back

The most valuable contribution is running a real session with this protocol and sharing what you learned:

- What worked? What didn't?
- Which rules were helpful vs. ceremonial?
- What's missing that you had to improvise?

Open an issue with your findings. Include a retro if you have one.

### Propose protocol changes

If you have a concrete improvement:

1. Open an issue describing the problem and your proposed solution
2. Reference the specific doc and section you'd change
3. If possible, include evidence from a real session where the current protocol fell short

Pull requests are welcome for:
- Typos and broken links
- Template improvements
- New examples from real sessions (add to `examples/`)
- Protocol doc changes (with rationale)

### Add examples

If you've run a session using this protocol, consider contributing your artifacts to `examples/`:

- Session charter
- WORKLOG (redact sensitive content)
- Retrospective
- Any protocol amendments you made

Real-world examples are more valuable than synthetic ones.

## What not to change

The invariant rules in `docs/PROTOCOL_CORE.md` section 3 are intentionally hard to change. If you think an invariant should change, open an issue first — don't submit a PR directly. These rules exist because they prevented real problems in real sessions.

## Style guidelines

- Keep docs human-readable — no jargon without explanation
- Use concrete examples over abstract principles
- Templates should be copy-paste ready with clear placeholder markers
- Cross-references between docs should use relative links and resolve to existing files
